# 斲然注音：新酷音核心整合設計

日期：2026-10-17（台灣時間）
狀態：設計草案，供使用者審閱；尚未整合 libchewing，尚未產生新 APK。
程式基準：v0.12；GitHub `work/virtual-keyboard`，提交 `ff9bdfc4add8b8275099fe6070a9f9265fc62758`。

## 1. 目的與範圍

讓使用者在 Android 上以手機虛擬鍵盤或藍牙／USB 英文 QWERTY 鍵盤，離線連續輸入繁體中文，並在正式送出前移動游標、局部選字與刪改。延續既有虛擬鍵盤及標準注音排列。

已確認的需求：亂序組字、同類聲母／介音／韻母替換、一般字詞轉換、連續組句、候選字翻頁、局部改字、組字 Enter 與 App 傳送動作分離。

本階段不加入其他注音配置、拼音、雲端服務、滑行輸入、語音、表情符號面板，以及個人詞庫編輯介面。原有英文字母、數字符號與切換其他輸入法按鈕保留。

## 2. 方案選擇與查證結果

選定 libchewing 作為第一順位整合核心：上游文件描述了依組字緩衝區上下文轉換、左右移動游標、向下開啟局部候選與 Enter 提交；已有 Android 使用案例。這是整合方向，尚非對本 App 可編譯、可執行的驗證結論。

備選方案為 McBopomofo 的 C++ 核心與 librime。前者需要自行完成 Android 與編輯操作橋接；後者輸入方案彈性高，但相依元件與設定範圍較大。這些成本比較是工程判斷，並非實測效能排名。

目前查證環境無法讀取 Codeberg，不能宣稱已核對其最新正式版。實作計畫須先解決可重現的來源取得，再選定版本。

## 3. 元件與資料歸屬

- **鍵盤與實體按鍵轉接**：將點按及 KeyEvent 轉為共同輸入動作；保留鍵位、工具列與 Android 系統快捷鍵。
- **輸入控制器**：依狀態解讀空白、數字、Enter、Esc、游標移動與候選點選。它是唯一寫入 App 編輯器的入口。
- **未完成音節**：沿用 v0.12 亂序與同類替換規則，保存當前尚未轉換的注音。只保存這一個音節，不再累積第二份完整句子。
- **Chewing 轉換介面**：封裝 native context、字詞轉換、組字串、游標、候選頁與選字；由核心持有已轉字、尚未提交的句子。UI 不直接呼叫 native 函式。
- **Android 編輯器轉接**：用 setComposingText / setComposingRegion 呈現組字及游標；僅在確認時 commitText。處理 App 切換、選取文字與生命週期。

未完成音節結束後，透過橋接將標準化注音交給核心轉換。不得讓 Kotlin 與 native 各自保存互不一致的已完成音節清單。實際採用的公開介面、原子失敗處理與輸入方式，須以選定版本的 API 驗證；不可假設可以直接插入任何內部資料結構。

每次輸入回傳一個完整快照：中文組字串、中文游標位置、尚未完成注音、候選頁、候選焦點、是否處理按鍵，以及本次要送出的文字。游標單位在轉接邊界明確換算為 Android UTF-16 位置；包含補充平面字元的案例必須驗證。

## 4. 狀態與操作

### 注音輸入中

- 同類注音替換，其他注音保留；重複相同符號為無操作，不增加歷史。
- 亂序輸入自動正規化。無效組合保留原內容並顯示短暫提示，不自動轉成英文。
- 聲調結束音節；空白結束一聲音節。轉出暫定中文後留在組字串，不正式送出。
- 退格移除最後一個有效輸入的注音；替換後不復活舊符號。
- Esc 只取消未完成音節，保留前面的中文組字。
- Enter 嘗試結束音節並確認整段文字；若該音節無法轉換，保留內容並提示，不能送出訊息或靜默刪除注音。
- 這一版不新增「已結束音節後連按聲調自動修改上一音節」的隱含規則。

### 中文組字中

- 接續注音開始下一音節，核心可以依上下文調整未鎖定的選字。
- 左右鍵移動組字串內游標；沒有組字時才交給 App。
- 向下或空白開啟游標對應字詞的候選。游標在末端時對應末字，在中間時對應游標左側字；位於起點則對應第一字。
- 使用者明確選過的字詞須維持選擇，除非他編輯對應音節或解除選擇。
- 退格刪除游標前一字及對應音節；在起點無操作，不越界刪除 App 內已提交文字。
- Enter 提交整段組字並清空狀態，本次按鍵不再觸發 App 的傳送／搜尋／換行。
- Esc 清空整段未提交組字。

### 選字中

- 方向鍵移動候選焦點；空白或 PageDown 下一頁，PageUp 上一頁，邊界停留原頁。
- 數字 1–9 對應本頁候選，0 對應第十個；無該項時保留狀態。
- Enter 或點選候選，更新字詞並回到中文組字狀態，不直接提交整句。
- 保留 F1–F9 作為本頁前九個候選的額外選字鍵；無候選時不攔截這些功能鍵。
- Esc 只關閉候選；退格關閉候選後依中文組字規則刪除。
- 本階段候選每頁最多十個；顯示頁碼與可翻頁方向，手機也能點按翻頁。

### 模式、標點與 App 行為

- 觸控 ABC 與單獨按放 Shift 可切換中英文。Shift 組合輸入大寫、全形切換或其他快捷鍵時，不額外切換語系。
- 切換英文或插入標點前，先嘗試確認組字；若存在無法轉換的音節，保留組字、提示原因，暫不切換或插入。提供明確的「保留注音原文送出」動作供使用者自行選擇。
- Ctrl／Alt／Meta 等快捷鍵優先交給系統或 App，除非是已明確定義的輸入法專用組合；不全面攔截。
- 無組字時，Enter 依 EditorInfo 執行完成、搜尋、下一步、傳送或換行。組字確認與 App 動作分兩次 Enter。
- 密碼與數字／電話欄位使用直接英數模式，停用中文組字與學習；保留刪除、確認及切換輸入法。
- 切換到另一個文字欄位時，不把上一欄的未完成內容提交到新欄位。清理前一輸入連線的組字狀態與 native context，且不將未確認內容當成學習資料。

## 5. Android、儲存與失敗處理

- 第一階段建置 arm64-v8a（使用者手機）與 x86_64（自動化驗證），延續 Android 8.0 以上支援目標。是否能達成由 native 編譯與執行結果判定。
- 系統詞庫隨 App 安裝，不需要網路下載；使用者資料放在 App 私有儲存空間。
- 本階段不提供學習介面。若核心預設會自動學習，先停用；若選定版本無法停用，須在實作前修改規格並說明，不默默啟用。
- native context 序列化存取並確實釋放；不因候選列重畫而重新載入詞庫。
- 核心或資料載入失敗時，不以舊小詞庫暗中替代。顯示中文核心不可用，讓使用者仍可輸入英數或切換其他輸入法。
- 不記錄使用者輸入內容於 Logcat、建置紀錄或錯誤回報。
- 字詞資料複製與更新採版本化及原子安裝，驗證失敗保留原可用資料。

另外，v0.10–v0.12 的 CI debug 簽章不固定，已造成更新必須移除舊版。這是交付問題，與轉換核心分開修正：發行測試新版前，要建立持續使用的私密簽章流程；私鑰不得提交到公開儲存庫或公開 Artifact。若目前權限無法配置，須明確告知安裝限制，不宣稱可覆蓋更新。

## 6. 驗收條件

1. 保留並通過 v0.12 的 14 項測試；新架構若替換內部類別，將原案例遷移到共同輸入行為測試。
2. 至少以「你好」「我想去台北」「今天天氣很好」驗證連續組句；可繼續輸入，不需逐字確認。這些案例不代表所有句子的首選必須永遠正確。
3. 從同音候選明確選定一字詞，接續輸入後該選擇不被任意改回。
4. 將游標移回句中，選字、刪除並繼續輸入，其他音節與已選字保持對齊。
5. 亂序、同類替換與替換後退格，在觸控與實體鍵盤動作序列下得到相同結果。
6. 候選十項、末頁不足十項、翻頁邊界，以及數字／注音鍵衝突均有自動化案例。
7. 以 EditorInfo 的傳送與搜尋欄位驗證：有組字的 Enter 不觸發 App 動作，無組字時才執行。
8. 無效音節、取消、切換模式、切換欄位、密碼欄位與 native 載入失敗，都不遺失或外洩未確認輸入。
9. 以含補充平面字元的文字驗證游標與刪除，不切斷 surrogate pair。
10. CI 原生編譯、核心整合測試與 APK 建置均通過；Android 執行測試驗證實際載入 native library 與詞庫，不能只用 Kotlin 單元測試代替。
11. 三星手機實測鍵盤顯示、觸控、外接鍵盤與第三方 App 相容性後，才能標示「手機驗證通過」。
12. 交付時分別列出已通過自動測試、尚未實測項目、依賴版本與安裝更新限制。
